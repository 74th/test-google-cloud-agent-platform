## MODIFIED Requirements

### Requirement: 長時間実行クエリジョブの疎通判定
検証手段はデプロイ済みエージェントに対して一意な検証試行として長時間実行クエリジョブを開始し、ジョブ名を保存し、終了状態または明示した監視期限まで監視できなければならない（SHALL）。検証は、ジョブ開始 API の成否、状態遷移、GCS 出力、および対象時間帯のコンテナログを収集し、少なくともルートパスへの HTTP 配送、クエリ処理の開始・終了、出力生成を区別して報告しなければならない（MUST）。証跡から確定できない段階を成功として扱ってはならず（MUST NOT）、不足した証跡と確認条件を記録しなければならない（MUST）。

#### Scenario: ルートパス経由で長時間ジョブが完了する
- **WHEN** ジョブ開始後にコンテナの `POST /` 受信ログ、対応する処理完了ログ、成功したジョブ最終状態、および期待する GCS 出力が確認できる
- **THEN** 検証結果は各証跡を同じ試行に関連付け、BYOC のルートエンドポイント経由で「動作確認」と報告する

#### Scenario: ルートパスへ配送されたが処理に失敗する
- **WHEN** 対象時間帯にコンテナの `POST /` 受信ログが見つかるが、要求の拒否、処理失敗、ジョブ失敗、または期待する出力の欠落が確認される
- **THEN** 検証結果は「配送確認・動作未確認」と報告し、HTTP 状態、ジョブ状態、処理ログ、出力のうち失敗または欠落した段階を示す

#### Scenario: ジョブは開始するがルートパスへの配送を確認できない
- **WHEN** ジョブ開始 API はジョブ名を返すが、十分なログ取り込み猶予後にも対象コンテナの `POST /` 受信ログが見つからない
- **THEN** 検証結果は「未到達」と報告し、確認した時間範囲、ジョブ状態、出力の有無、対象リソース、およびログ検索条件を示す

#### Scenario: 証跡不足で判定できない
- **WHEN** 権限不足、ログ欠落、監視期限超過、試行を一意に関連付けられないなどの理由でいずれかの段階を確定できない
- **THEN** 検証結果は「判定不能」と報告し、不足した証跡、原因、および確定できた段階だけを示す
