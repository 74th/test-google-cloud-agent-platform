## ADDED Requirements

### Requirement: 長時間ジョブのルートエンドポイント
ランタイムは GCS 入力から配送される長時間ジョブを `POST /` で受け付け、非ストリーミングの `query` として処理しなければならない（SHALL）。ルートエンドポイントは長時間ジョブの入力形式を通常操作の配送形式と区別して正規化し、成功時は `output` を含む JSON オブジェクトを返さなければならない（MUST）。

#### Scenario: GCS 経由入力の成功
- **WHEN** ルートエンドポイントが有効な検証識別子を含む長時間ジョブ入力を受信する
- **THEN** ランタイムはその入力を `query` として処理し、HTTP 200 と `output` を含む JSON 応答を返す

#### Scenario: 通常操作の互換性
- **WHEN** 通常の Agent Platform 操作用エンドポイントが操作名を含む既存形式を受信する
- **THEN** ランタイムは従来と同じ操作選択、入力検証、応答形式を維持する

#### Scenario: 不正な長時間ジョブ入力
- **WHEN** ルートエンドポイントが必要な検証入力を欠く、または許可されない操作を指定した入力を受信する
- **THEN** ランタイムはクエリを開始せず、クライアントが判別できる4xxエラーを返す

## MODIFIED Requirements

### Requirement: 非ストリーミングクエリ
ランタイムは `query` および `async_query` 操作を受け付けなければならない（SHALL）。各操作は既定ではリクエストの処理開始から10秒を目安に待機した後、`OK` を含む単一の最終応答を返さなければならない（SHALL）。長時間ジョブの検証入力では安全な上限内の処理時間を指定でき、その時間もイベントループをブロックせずに待機しなければならない（MUST）。

#### Scenario: query の成功
- **WHEN** 処理時間を指定しない有効な `query` リクエストを受信する
- **THEN** ランタイムは処理開始から約10秒後に `OK` を含む単一の応答を返す

#### Scenario: async_query の成功
- **WHEN** 処理時間を指定しない有効な `async_query` リクエストを受信する
- **THEN** ランタイムはイベントループをブロックせず、処理開始から約10秒後に `OK` を含む単一の応答を返す

#### Scenario: 15分を超える検証処理
- **WHEN** 長時間ジョブ入力が許可範囲内の15分を超える処理時間を指定する
- **THEN** ランタイムはイベントループをブロックせず指定時間後に `OK` を含む単一の応答を返す

#### Scenario: 許可範囲外の処理時間
- **WHEN** 長時間ジョブ入力が負数または設定された上限を超える処理時間を指定する
- **THEN** ランタイムは処理を開始せず4xxエラーを返す
