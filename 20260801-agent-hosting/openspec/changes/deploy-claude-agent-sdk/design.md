## Context

現在のリポジトリには最小限の Python エントリーポイントだけがあり、デプロイ済みサービスは存在しない。背景は `proposal.md` を参照すること。最初の段階では、計画中の Streamlit コンテナを導入する前に、バックエンドをホストする境界を検証しなければならない。

サービスは Google Cloud Agent Platform に提供するコンテナ内で Claude Agent SDK エージェントを実行し、プロジェクト `nnyn-dev` にデプロイ可能であり、開発者のローカル Python プロセスから呼び出せなければならない。Claude 認証情報と Google Cloud 認証情報は機微情報であり、コミットしてはならない。エージェントのバスデータは利用者から提供された静的知識であり、アプリケーションと一貫してデプロイする必要がある。

## Goals / Non-Goals

**目標:**

- ホストされた Claude エージェントについて、再現可能なビルド、デプロイ、ローカル呼び出しの経路を一つ確立する。
- ローカルのスモークテストクライアントがプロンプトと応答テキストだけを扱えるよう、プロバイダー向けエージェントプロトコルを小さなサービスアダプターの背後に隠す。
- 時刻表を Claude Agent SDK のスキルとしてパッケージ化し、決定的な路線選択の指示を明確にする。
- 運用設定、必要な ID、検証手順をリポジトリのドキュメントから見つけられるようにする。

**対象外:**

- Streamlit Chat UI の構築、デプロイ、連携。
- リアルタイムのバスデータ、運行カレンダー、または正式な交通データ連携の提供。
- 複数ターンの会話、ユーザーアカウント、会話履歴の永続化。
- Google Cloud プロジェクト、課金、IAM ロール、Anthropic 認証情報の自動プロビジョニング。

## Decisions

### コンテナ化したエージェントランタイムと限定的なテキストアダプターを使用する

コンテナは、選択した Google Cloud Agent Platform ランタイムが求める HTTP または呼び出し契約を通じて Claude Agent SDK アプリケーションを起動する。小さなアダプターが、その契約を SDK に送る単一のプロンプトへ変換し、最終的なテキスト回答を呼び出し元向けに正規化する。

この構成はホスティングプロトコルの詳細をエージェントロジックから分離し、後で追加する Streamlit UI を独立した呼び出し元にする。ローカルスクリプトから Claude を直接呼び出す案ではホストされたサービス境界を検証できず、プロバイダー固有のストリーミングイベントをクライアントに公開する案ではスモークテストが SDK 内部に不必要に結び付く。

### バス時刻表をリポジトリ内のスキルとして保存する

スキルの唯一の参照元は `workspace/.claude/skills/bus-schedule/SKILL.md` とする。コンテナのビルド時に、このファイルを Claude Agent SDK がサポートするスキル検出レイアウトへ取り込む。日本語名 `金沢テストバス時刻表` を維持し、架空の金沢地域の路線、既定の路線選択、および所要時間の長い兼六・ひがし茶屋コースへの注意は、このファイルに定義された内容を使用する。

これにより、ドメイン知識をレビュー可能かつバージョン管理可能にし、すべてのデプロイで利用できるようにする。また、同一の時刻表を複数箇所で管理して内容がずれることを防ぐ。静的な概念実証データにデータベースやリモート検索元は不要であり、目標と無関係な運用依存を導入することになる。

### 「次」を日本標準時と提供済み時刻表だけで判定する

エージェントの指示は、路線指定のない次のバスの質問を `Asia/Tokyo` の現在時刻で評価し、既定を金沢さくら台三丁目 → 金沢みらい駅とする。現在時刻以降で最初の時刻表上の出発便を選び、残りの便がない場合はその旨を説明し、掲載された所要約25分の兼六・ひがし茶屋コースだけを金沢テスト病院経由として注意する。

ホストランタイムの既定タイムゾーンを使うと誤った回答になるおそれがあり、呼び出し元に時刻指定を求めると自然言語のスモークテストが弱くなる。外部のリアルタイム時刻表ソースは問い合わせないため、回答は提供されたデータの範囲にとどまる。

### デプロイ設定を明示し、シークレットを外部管理する

リポジトリには、プロジェクト（既定値は `nnyn-dev`）、ロケーション、イメージまたはアーティファクト設定、エージェントランタイムのデプロイ先を明示的な入力として受け取るデプロイスクリプトを含める。スクリプトは実行前に非シークレット値を検証し、文書化された Google Cloud ワークフローを通じてコンテナをビルド・公開し、エージェントをデプロイして、デプロイ識別子またはエンドポイントを出力する。

Claude の認証情報は、現行の Agent Platform ドキュメントに基づいて選択する、承認済みの Google Cloud シークレット／環境変数の仕組みで注入する。認証情報をソース、イメージ、コマンド出力、コミット済み設定に含めてはならない。コミットする `.env.example` には値を含めず、必須変数名だけを記載してよい。手動コンソールでのデプロイは、再現・レビューできないため採用しない。

### ローカルクライアントを簡潔な認証付きスモークテストツールにする

Python クライアントは Application Default Credentials または文書化されたローカル認証フローで Google Cloud 認証情報を取得し、引数または環境変数からデプロイ先を読み取り、プロンプトを送信して返却テキストを出力する。設定不足、認証失敗、エンドポイントの利用不可、不正なレスポンスについては明確に失敗する。

クライアントはコンテナを直接呼び出すのではなく、デプロイ済みの Agent Platform インターフェースを呼び出す。これにより実際の本番相当の入口を検証する。これは意図的に Web サーバーや汎用チャット UI にはしない。

## Risks / Trade-offs

- [Agent Platform のコンテナプロトコルまたはデプロイコマンドがリージョン／バージョンごとに異なる] → 実装時に最新の公式ランタイム契約を確認し、デプロイスクリプトとアダプターに閉じ込める。
- [Claude 認証情報の露出] → シークレット注入を使い、コマンドエラーをマスクし、例には変数名のみを示し、レビュー工程にシークレットスキャンを加える。
- [LLM が時刻表の指示を一貫して適用しない] → 正確な日本語スキル指示を使用し、対応していれば固定時刻または制御されたプロンプトでテストし、統合テストで必須の路線／時刻／注意事項を検証する。
- [現在時刻を尋ねる質問は時刻に依存する] → 制御可能な時計または明示的なテスト時刻を含むプロンプトで時刻表のアサーションを実行し、エンドツーエンド接続用にはライブスモークテストだけを残す。
- [デプロイにクラウドコストが発生する、または権限が不足する] → 前提条件を文書化し、可能な場合はリソース作成前のドライ検証をサポートし、クリーンアップ識別子をデプロイ出力で確認可能にする。

## Migration Plan

1. `nnyn-dev` の対象リージョンについて、サポートされた Google Cloud Agent Platform コンテナランタイム契約と必要な API を確認する。
2. コンテナ、スキル、アダプター、デプロイスクリプト、ローカルスモークテストクライアントを実装し、本番認証情報を埋め込まずにローカルで検証する。
3. `nnyn-dev` に認証し、必要なアーティファクトおよびエージェントリソースを作成または選択して、デプロイスクリプトを実行する。
4. 出力されたデプロイ識別子またはエンドポイントをローカルで設定し、`次のバスは何時？` を呼び出す。成功結果を実装検証の記録に残す。
5. 文書化されたクリーンアップコマンドに従って新規作成したエージェントデプロイとイメージを削除し、ロールバックする。既存リポジトリに保護すべきデプロイ済み動作はない。

## Open Questions

- この検証をホストする Google Cloud のリージョンと Agent Platform 環境はどれか。プロジェクト標準が決まるまで、デプロイスクリプトはロケーションの明示指定を必須とする。
- `nnyn-dev` には Claude 認証情報用の承認済み Secret Manager シークレットがすでにあるか。それともデプロイ前に運用者が作成する必要があるか。
