# Spec Delta

## Purpose

CLI を通して、GKE Agent Sandbox の Egress 制御、ワークスペース永続化、カーネル分離が期待どおりに動くかを再現可能な手順で確認し、結果を証跡として残す。

## ADDED Requirements

### Requirement: 許可した宛先は要約できる
検証手順では、CLI で `https://github.com/74th` の要約を依頼し、応答にそのページの内容に基づく要約が含まれることを確認しなければならない（SHALL）。

#### Scenario: GitHub プロフィールの要約
- **WHEN** 検証スクリプトが「https://github.com/74th を要約して」というプロンプトで CLI を実行する
- **THEN** 応答にアカウント 74th の公開情報（リポジトリなど）に基づく要約が含まれ、検証は成功と判定される

### Requirement: 未許可の宛先は要約できない
検証手順では、CLI で `https://www.tohoho-web.com/` の要約を依頼し、ページを取得できなかったことを確認しなければならない（SHALL）。あわせて、同じ時間帯に Sandbox Pod から当該宛先への通信が拒否されたことを、Pod 内からの直接接続試験またはネットワークポリシーのログで確認しなければならない（SHALL）。

#### Scenario: tohoho-web の要約に失敗する
- **WHEN** 検証スクリプトが「https://www.tohoho-web.com/ を要約して」というプロンプトで CLI を実行する
- **THEN** 応答はページを取得できなかったことを示し、ページ内容に基づく要約は含まれない。また、通信拒否の証跡が記録される

### Requirement: ワークスペースの永続化を確認する
検証手順では、次の 4 点をすべて確認しなければならない（SHALL）。
(1) 1 回目の実行で、CLI が生成したランダムなトークンをエージェントにワークスペースのファイルへ書かせる。
(2) 同じセッション ID で 2 回目を実行したとき、Pod UID が 1 回目と異なる（Pod が作り直されている）。それにもかかわらず、実行開始前のワークスペースのファイル一覧に当該ファイルが存在し、エージェントがファイルから読んだトークンが一致する。
(3) 2 回目の応答が 1 回目の会話内容を踏まえている（Claude セッションの再開）。
(4) 別の新しいセッションでは、当該ファイルが存在しない。

#### Scenario: 同じセッションでファイルが引き継がれる
- **WHEN** 検証スクリプトが同じセッション ID で 2 回目の実行を行う
- **THEN** 2 回目の Pod UID は 1 回目と異なり、実行開始前のファイル一覧にトークンファイルが含まれ、応答のトークンが 1 回目に書かせた値と一致する

#### Scenario: 別セッションではファイルが見えない
- **WHEN** 検証スクリプトが新しいセッションで同じファイルの読み取りを依頼する
- **THEN** 実行開始前のファイル一覧にトークンファイルは含まれず、エージェントはファイルが存在しないと応答する

### Requirement: カーネル分離を確認する
検証手順では、各実行のメタデータから、Sandbox Pod が gVisor RuntimeClass で gVisor ノード上で実行されたことを確認しなければならない（SHALL）。

#### Scenario: gVisor 上での実行を確認する
- **WHEN** 検証スクリプトが実行メタデータと Pod の spec を確認する
- **THEN** `runtimeClassName` が `gvisor` で、カーネル情報が gVisor のものであることが確認できる

### Requirement: 検証結果を証跡として残す
検証スクリプトは、各検証項目の判定（成功または失敗）、使用したセッション ID、応答の抜粋、実行メタデータを、日付付きの証跡ファイルとして `evidence/` に保存しなければならない（SHALL）。

#### Scenario: 証跡ファイルが作成される
- **WHEN** 検証スクリプトの実行が完了する
- **THEN** `evidence/` に日付付きのファイルが作成され、すべての検証項目の判定が記録されている
